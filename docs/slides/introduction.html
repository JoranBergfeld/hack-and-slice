Start with a digit

An image is a grid of numbers: dark and light pixels.

Pixel values → hidden layer → ReLU → dropout → output layer → 10 logits

One output score per digit, 0 through 9. The largest score wins.

Facilitator notes

Imagine a handwritten 7. The input is numerical pixel values, not the word "seven". Flatten the grid into a list for this simple architecture. We are not training a digit model in the guided exercise; it is a familiar mental model before text.

3 / 16 · 2 minutes

A layer combines evidence

A linear layer has learned weights and biases.

2 × 0.5 + (-1) × 1 + 0.25 = 0.25

  • ReLU: [-2, 0.25, 3] → [0, 0.25, 3].
  • Without a nonlinearity, stacked linear layers remain one linear transformation.
  • Dropout randomly omits activations during training; it is off for evaluation and prediction.
Facilitator notes

Ask participants to check the weighted sum. The two-input example is only one unit, not a full image calculation. Weights and biases start as initialized numbers and are learned. ReLU lets the model represent more than a linear transformation. Dropout reduces reliance on particular activations; it does not permanently delete units. We omit dropout's training-time rescaling from this small explanation.

4 / 16 · 1.5 minutes

Scores are not probabilities

For a toy two-class problem:

ClassLogitSoftmax probability
A0about 0.27
B1about 0.73

Softmax turns scores into probabilities that sum to 1. Prediction chooses B either way.

Digits have 10 scores; our banking classifier will have 77.

Facilitator notes

These are invented logits to illustrate the distinction. Probabilities are not a guarantee of correctness. Softmax preserves the winning class, so we do not need it just to choose a label. Negative logits are also valid scores.

5 / 16 · 2 minutes

Training needs a correct label

Cross-entropy penalizes low probability for the correct class.

Probability of correct labelLoss: minus natural log
0.50about 0.69
0.90about 0.11
0.10about 2.30

Smaller loss is better. A confident wrong prediction is expensive.

PyTorch cross-entropy takes logits directly; do not apply softmax first.

Facilitator notes

Ask which row describes a better prediction for the known label. No calculus or log derivation needed: use the table as an intuition for the penalty. The two-class example becomes the same operation over ten digits or 77 intents. PyTorch handles log-softmax internally.

6 / 16 · 2 minutes

How do the numbers improve?

Labeled batch → logits → loss → gradients → optimizer update → repeat

  • A gradient tells how a parameter change affects loss locally.
  • Toy plain gradient step: weight 0.50, gradient +2, learning rate 0.01 → weight 0.48.
  • Automatic differentiation computes gradients. You do not implement backpropagation.
Facilitator notes

The toy arithmetic is 0.50 minus 0.01 times 2, a plain gradient-descent step, not an Adam calculation. A positive gradient suggests decreasing this weight; a negative gradient suggests increasing it. Local direction is not a promise that every batch or validation score improves. Training uses many parameters at once.

7 / 16 · 1.5 minutes

Adam takes the steps

  • Adam uses recent gradient direction and size to adapt parameter updates.
  • The learning rate controls the update scale; it is not the exact step of every weight.
  • Too large can destabilize learning. Too small can make progress slow.
  • Use PyTorch Adam with default optimizer parameters and no weight decay.

0.001 is a starting learning rate, not a proven best value.

Facilitator notes

Adam is provided, not a participant implementation exercise. Do not derive its formula. Compare the direction and scale intuition with the previous toy step, while explicitly distinguishing Adam's adapted updates from that plain step. We will compare chosen configurations rather than assume a universal best learning rate.

A batch groups examples for one update. An epoch is one pass through training examples.

Shuffle training data each epoch. Validation runs without updates or dropout.

Facilitator notes

Keep the digit example in mind: repeatedly practicing the same images is not an independent exam. Ask why selecting a learning rate using the test score would spoil that exam. The test set is public, but keeping it out of development is a participant agreement, not special enforcement machinery.

Keep the best validation checkpoint

Invented validation accuracies, with patience 3:

Epoch: 1, 2, 3, 4, 5
Accuracy: 50%, 60%, 60%, 59%, 58%

  • No improvement for three epochs: stop after epoch 5.
  • Use epoch 2, not the last weights. Equal accuracy keeps the earliest epoch.
  • Training loss may keep falling while validation stalls: memorizing is not generalizing.
Facilitator notes

Ask which checkpoint to keep. This example uses strict improvement in validation accuracy: epochs 3, 4 and 5 count toward patience. The epoch limit is a separate cap. These are invented values, not a Banking77 training result. A latest resumable snapshot serves recovery; it is separate from the best-validation model used for selection.

Now replace pixels with text

Banking77: customer messages labeled with 77 banking intents.

"My card hasn't arrived." → tokens → IDs → learned vectors → mean → classifier → 77 logits

The loss, gradients, Adam and split roles stay the same. The input representation changes.

Facilitator notes

This is the architecture participants actually build. An intent is the message's category, not a generated answer. We learn from scratch, including the word vectors; no pretrained encoder is part of the guided exercise.

11 / 16 · 2 minutes

Token IDs identify words, not meanings

Lowercase, then tokenize with [a-z0-9']+:

"My card hasn't arrived." → ["my", "card", "hasn't", "arrived"]

  • Build the vocabulary only from training messages; keep tokens seen at least twice.
  • Reserve 0 for <unk>. Unseen tokens map there.
  • "???" has no tokens: use one <unk> so averaging is defined.
  • A larger ID does not mean a more important or more similar word.
Facilitator notes

Validation and test messages must not influence the vocabulary. Ask what happens to a brand-new word at prediction time. A toy vocabulary might map "card" to 1 and "arrived" to 2; actual IDs come from the saved training vocabulary, not this slide. The apostrophe in "hasn't" stays inside its token.

12 / 16 · 1.5 minutes

Look up vectors, then average

Illustrative two-dimensional embeddings:

[1, 0] and [0, 2] → mean [0.5, 1]

  • Embeddings are learned parameters, updated along with classifier weights.
  • Mean pooling makes one fixed-size vector from any number of tokens.
  • Reversing the tokens gives the same mean: word order is lost.

PyTorch mean-mode EmbeddingBag combines lookup and pooling.

Facilitator notes

Ask the audience to average each coordinate. These numbers are illustrative, not actual learned word vectors. The vector's coordinates are not hand-assigned language features. Repetition can change the mean, but reordering cannot. Pretrained embeddings are an optional next step after this from-scratch exercise.

13 / 16 · 1 minute

The text-classifier equivalent

Mean embedding → linear hidden layer → ReLU → dropout → linear output → 77 intent logits

  • Start with embedding size 64, hidden size 128, dropout 0.3.
  • Sizes and dropout are configurable starting values, not fixed rules.
  • Predict the highest-scoring official intent label.
Facilitator notes

Connect the layers to the digit architecture. The number of outputs is tied to Banking77's 77 labels; embedding and hidden widths are choices. Cross-entropy still receives logits. Save the vocabulary and official-label-to-index mapping with the weights, not just the weights alone.

Compare your chosen configurations

  • Choose at least two; vary learning rate, batch size, epoch limit, early-stopping settings, embedding size, hidden size or dropout.
  • Keep the architecture sequence, Adam, seed 42, split and preprocessing shared.
  • Inspect training loss, validation accuracy, comparison charts and validation predictions.
  • Choose highest validation accuracy; tied runs use configuration-list order.

Suggestions: learning rates 0.0003 / 0.001 / 0.003; batch size 64; epoch limit 30; patience 3. Not a mandatory three-rate sweep.

Facilitator notes

For example, keep everything fixed except learning rate in two configurations, or instead compare two hidden sizes. No fixed maximum, but more runs take time and may incur Azure charges. Select only when every chosen configuration has valid matching results; do not silently choose from a partial comparison. The configuration chart is not limited to learning rates.

15 / 16 · 1.5 minutes

Then evaluate once and predict locally

  • Official training data: 10,003 → 9,002 training + 1,001 validation, intent-stratified with seed 42.
  • Official held-out test: 3,080 messages, for one final evaluation after selection.
  • Accuracy is the fraction correct; macro-F1 averages per-intent F1, giving each intent equal weight.
  • Label a separate demonstration message using the saved model, vocabulary, label mapping and same preprocessing.
Facilitator notes

F1 balances precision (how often predictions of an intent are right) and recall (how many examples of that intent are found). Participants implement accuracy and macro-F1 in the written challenges. Evaluation and demonstration-message prediction run locally on CPU, whether training ran locally or on Azure. A demonstration is not a benchmark or evidence of general accuracy.
